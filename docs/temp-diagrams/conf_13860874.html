Scenario #1 — 폐관 후 침입자 감지

T1이 사람을 감지하고 재촬영 후, 지속 감지 시 Gen.G가 출동해 PIR과 카메라로 현장을 재확인합니다.

  1. 관리자가 Unity에서 폐관 보안 모드를 실행한다.

  2. T1이 지정된 순찰 경로를 이동하며 RealSense RGB 영상과 Depth를 Main Server로 전송한다.

  3. Main Server가 YOLO로 사람을 감지하면 Unity에 WATCHYellow 경고와 위치를 표시하고 T1에 재촬영을 요청한다.

  4. 사람이 금지 구역에서 계속 감지되면 CHECKRed로 변경하고 Gen.G를 안전거리 확인 지점으로 출동시킨다.

  5. Gen.G가 PIR과 Pi Camera RGB 영상으로 현장을 재확인한다.

  6. 사람과 움직임이 없으면 관리자가 오탐 종료를 승인하고 Gen.G는 대기 위치로 복귀한다.

  7. 사람 또는 움직임이 확인되면 DANGERRed로 변경하고 Unity에 112 신고 요청과 차단벽 폐쇄 요청을 표시한다.

  8. 감지 영상, 위치, 출동 시간과 관리자 판단을 DB에 저장한다.

Scenario #2 — 중요 전시품 분실·이동 감지

T1의 기준 촬영 데이터와 현재 RGB/Depth를 비교하고, 불일치가 지속되면 Gen.G가 다른 각도에서 재확인합니다.

  1. T1이 지정된 위치와 각도에서 전시품을 촬영하고 RGB 영상·Depth를 Main Server로 전송한다.

  2. Main Server가 YOLO 결과와 기준 이미지·Depth를 비교한다.

  3. 전시품이 인식되지 않거나 위치가 다르면 WATCHYellow로 변경하고 T1이 최대 2회 재촬영한다.

  4. 재촬영에서 전시품이 확인되면 정상으로 복귀한다.

  5. 계속 확인되지 않으면 CHECKRed로 변경하고 Gen.G를 다른 각도의 확인 지점으로 출동시킨다.

  6. Main Server가 Gen.G의 Pi Camera RGB 영상을 추가 분석한다.

  7. 전시품이 확인되면 오탐 종료한다.

  8. 두 로봇 영상에서 모두 확인되지 않으면 DANGERRed로 변경하고 Unity에 신고 요청과 차단벽 폐쇄 요청을 표시한다.

  9. 기준 이미지, 확인 영상, Depth와 관리자 판단을 DB에 저장한다.

Scenario #3 — 화재 의심 즉시 대응

불꽃·연기 의심 객체 감지 시 즉시 위험 확인으로 전환하고, Gen.G가 온도·레이저 센서와 영상으로 화재 징후를 재확인하며 EVACUATE 시 워터 펌프로 모의 진압합니다.

  1. T1이 RealSense RGB 영상과 Depth를 Main Server로 전송하며 순찰한다.

  2. Main Server가 화재 이미지·불꽃·연기 의심 객체를 감지하면 즉시 DANGERRed로 변경한다.

  3. Unity에 빨간 경고와 T1 영상을 표시하고 Gen.G를 안전거리 확인 지점으로 즉시 출동시킨다.

  4. Gen.G가 Pi Camera RGB 영상, 온도 센서값, 레이저 감지 여부를 Main Server로 전송한다.

  5. 화재 징후가 없으면 관리자가 영상을 확인한 뒤 오탐 종료한다.

  6. 영상 또는 센서에서 화재가 재확인되면 EVACUATERed로 변경한다.

  7. Unity에 119 신고 요청과 차단벽 폐쇄 요청을 표시하고, Gen.G 워터 펌프 분사를 시작하며, 두 로봇을 안전 위치로 이동시킨다.

  8. 영상, 온도·레이저 센서값, 출동 경로, 워터 펌프 동작 로그와 관리자 판단을 DB에 저장한다.

Scenario #4 — 개장 중 전시품 접촉 감지

관람객 손 또는 장난감 손이 보호 구역에 진입하면 음성 안내와 현장 확인을 단계적으로 수행합니다.

  1. 관리자가 Unity에서 개장 운영 모드를 실행하고 T1이 저속 순찰을 시작한다.

  2. T1이 RGB 영상과 Depth를 Main Server로 전송한다.

  3. Main Server가 손 또는 장난감 손이 전시품 보호 구역에 들어온 것을 감지하면 WATCHYellow로 변경한다.

  4. T1이 안전거리에서 1차 음성 안내를 출력한다.

  5. 손이 보호 구역에서 벗어나면 일정 시간 관찰 후 정상 종료한다.

  6. 접촉이 계속되면 CHECKRed로 변경하고 Gen.G를 출동시킨다.

  7. Gen.G가 Pi Camera RGB 영상으로 재확인하고 2차 음성 경고를 출력한다.

  8. 접촉이 계속되면 DANGERRed와 관리자 확인 요청을 표시하고 영상·접촉 시간을 DB에 저장한다.

Scenario #5 — 배터리 부족 및 순찰 임무 인계

T1의 배터리가 기준 이하이면 Gen.G에 남은 waypoint를 인계하고, T1은 ArUco 마커 기반 정밀 주차 후 수동 충전 연결을 요청합니다. (자동 충전독 미구현 — 검토 결과 현 단계 제외)

  1. T1이 배터리 잔량과 현재 waypoint를 Main Server로 전송한다.

  2. 배터리가 기준 이하이면 Unity에 배터리 부족을 표시하고 Main Server가 Gen.G의 상태를 확인한다.

  3. Gen.G가 정상이라면 남은 순찰 waypoint를 전달해 순찰 임무를 인계한다.

  4. T1은 충전소 앞 대기 지점으로 이동하고, 충전소에 도착하면 ArUco 마커를 인식해 정밀 주차를 시작한다.

  5. 정밀 주차가 기준 오차 안에서 완료되면 Unity에 수동 충전 연결 요청을 표시한다. (자동 충전독 미구현)

  6. ArUco 인식 또는 정밀 주차에 실패하면 T1을 안전 정지시키고 Unity에 긴급 수동 충전 요청을 표시한다.

  7. 관리자가 실패 원인을 확인한 뒤 T1을 수동으로 충전하고 복귀를 승인한다.

  8. 배터리 부족, 임무 인계, ArUco 주차 성공·실패와 충전 결과를 DB에 저장한다.
